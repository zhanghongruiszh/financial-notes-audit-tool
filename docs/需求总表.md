## 七、匹配与勾稽的硬逻辑（2026-11-20 定稿，按此实现，不再自创）

**分类文档的唯一用途**：Word 附注 ↔ 报表 的匹配。
不用于编号治理、不用于版面、不用于任何其他环节。

### 7.1 报表项目（分类表中的「报表项目」）

匹配对象：**Word 附注的小标题**（子项目标题）。

| 报表金额 | 能否匹配到 Word 标题 | 处理 |
|---|---|---|
| 有金额 | 能匹配 | **做数字勾稽**：报表金额 ↔ Word 该标题下的**合计数** |
| 0 / 空 | 不能匹配 | **正常，没有这项** —— 不报错、不进未披露、不显示 |
| 0 / 空 | 能匹配 | **按金额 0 做勾稽**（附注侧合计数应为 0，若有数即为差异） |
| 有金额 | 不能匹配 | **漏项** → 进「未披露」，作为人工判断 |

### 7.2 子项（分类表中的「子项」）

匹配对象：**所属报表项目的 Word 标题下、表格中的对应行**。

1. 先定归属的报表项目：**语义判断，取顺序上最近的一个报表项目**
   （一般在上方或下方的第一个报表项目）
2. 再在该项目的 Word 表格里找同名行
3. 找到 → 行级数字勾稽；找不到 → 记为该项目的子项未披露（人工判断）

### 7.3 合计项（分类表中的「合计项」）

不参与上面两套匹配。它只是加总结果：
- 不与 Word 标题匹配
- 不进未披露
- 只用于报表内部恒等式（`report_relations.py`）

1. **子项归属**："顺序上最近"我按报表的阅读顺序（先左段后右段、从上到下），
