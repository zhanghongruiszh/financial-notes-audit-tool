## 六、报表数据的规范化处理（本轮新增要求，重要）

你的原话拆成四条，全部记为必须实现：

| # | 要求 | 状态 |
|---|---|---|
| R21 | 报表**先做数据处理**：三大表分左右两段，**先左段后右段** | ✅ `report_items.ordered_items` |
| R22 | 工作表顺序固定为 **资产负债表 → 利润表 → 现金流量表 → 所有者权益表**（不依赖文件里的物理顺序） | ✅ `SHEET_ORDER` |
| R23 | 每一行分成两类：**报表项目** 与 **子项** | ✅ `classify()`：line / sub / total / section |
| R24 | **报表项目 ↔ Word 主要附注的标题**匹配 | ⚠️ 分类已做，匹配待接 |
| R25 | **子项 ↔ 该标题下方表格的行**匹配 | ⚠️ 同上 |

`report_items.py` 现状（张江实测）：

```
工作表顺序：资产负债表 → 利润表 → 现金流量表   ✓
分类统计：报表项目 193、子项 16、合计项 23、分段标题 10   ✓
营业总收入 → 合计项；营业收入 → 报表项目
营业总成本 → 合计项；营业成本/税金及附加/销售费用… → 报表项目
```

**为什么这个顺序重要**：之前的匹配是"拿报表项目去全文档找同名行"，
所以会把「营业成本」错挂到别处、把「税金及附加」当成子项跳过。
按"左右分段 + 先标题后行"的结构去匹配，才和会计上的层级一致。
