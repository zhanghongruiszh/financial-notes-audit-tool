## 七、匹配与勾稽的硬逻辑（2026-11-20 定稿，按此实现，不再自创）

**分类文档的唯一用途**：Word 附注 ↔ 报表 的匹配。

### 7.1 报表项目（分类表中的「报表项目」）

匹配对象：**Word 附注的小标题**（子项目标题）。

| 报表金额 | 能否匹配到 Word 标题 | 处理 |
|---|---|---|
| 有金额 | 能匹配 | **做数字勾稽**：报表金额 ↔ Word 该标题下的**合计数** |
| 0 / 空 | 不能匹配 | **正常，没有这项** —— 不报错、不进未披露、不显示 |
| 0 / 空 | 能匹配 | **按金额 0 做勾稽**（附注侧合计数应为 0，若有数即为差异） |
| 有金额 | 不能匹配 | **漏项** → 进「未披露」，作为人工判断 |

### 7.2 子项（分类表中的「子项」）

匹配对象：**所属报表项目的 Word 标题下、表格中的对应行**。

1. 先定归属的报表项目：**上下都能找，由我判断选哪个**。一般规律：
   - **资产负债表、利润表 → 往上找**（上方的第一个报表项目）
   - **现金流量表 → 往下找**（下方的第一个报表项目）
2. 再在该项目的 Word 表格里找同名行
3. 找到 → 行级数字勾稽；找不到 → 记为该项目的子项未披露（人工判断）

## 八、资产类附注表的勾稽公式（会计准则口径，硬规则）

依据《企业会计准则》对"账面余额 / 账面净值 / 账面价值"的定义
（参见 [账面余额与账面价值的区别](http://www.chanjet.net/news.asp?id=5684)）：

```
账面余额 = 原值（原价）
账面净值 = 原值 − 累计折旧（或累计摊销）
账面价值 = 账面净值 − 减值准备
```

### 8.1 触发条件（不需要识别表类型）

**只要表里同时出现"原值/原价"行和"累计折旧/累计摊销"行**，下面两条就必须成立：

| 关系 | 说明 |
|---|---|
| 净值 = 原值 − 累计折旧(摊销) | 每一列都要核（期初、期末、增加、减少…） |
| 价值 = 净值 − 减值准备 | **减值行不存在或为空，按 0 处理**，仍要核 |

覆盖范围：固定资产、无形资产、使用权资产、投资性房地产、长期待摊费用，
以及任何带"原值 + 折旧/摊销"的明细表。**不依赖表类型识别结果**——
以前只在识别成"资产增减变动表"时才跑，识别不到就漏了。

### 8.2 三种缺项都要报

| 情形 | 处理 |
|---|---|
| 原值、折旧都有数，净值列是空 | 报「账面净值漏填」，期望值 = 原值 − 折旧 |
| 净值有数、账面价值列是空 | 报「账面价值漏填」 |
| 整表没有净值行，但有原值/折旧/价值 | 直接核 价值 = 原值 − 折旧 − 减值 |

### 8.3 实现落点

`rules._rule_asset_blocks()`，规则号 `R-ABLK`；由 `build_checks` 对每张表无条件调用
（不再按表类型过滤）。

## 十、空模板（无金额）的支持情况（实测，不是猜）

用 `附注模板/一般企业模板6.4财务报表附注.doc` 实测（转 docx 后直接跑结构识别）：

| 指标 | 结果 |
|---|---|
| 识别章节 | 2 章 |
| 识别子项目 | 85 个 |
| 识别表格 | 163 张 |
| 数据列 | 527 列，**已判角色 356 列**（余额 211、金额 62、准备 35、价值 31、减少 28、增加 22、比例 14、折旧 3） |
| 无角色列 | 171 列 |
| 生成勾稽项 | **425 条**（V-SUM 137、R-NET 76、R-MOVE 75、V-GRP 65、R-PCT 40、R-BLK 23、R-SUMD 9） |

**结论：空模板不是"识别不了"** —— 结构、列角色、勾稽项都能从表头语义推出来。

空模板真正的限制只有一个：**没有期间**（模板里没有"期末指20XX年12月31日"这类定义，
也没有日期表头），所以列被标成"期间待确认"，勾稽项无法落到具体期间。

解决办法（已实现）：有报表时用 `report_reader` 的期间做兜底
（`cross_checks._report_periods`：报表里大日期=本期、小日期=上期）。
**这也是为什么需要带金额的样本**：不是为了凑数，是为了拿到期间和口径。
