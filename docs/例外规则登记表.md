# 例外规则登记表（Exception Registry）

> **目的**：测试项目（铁联化轻、张江集团单体）不是目标，只是**探测器**。
> 用它找出「通用逻辑覆盖不了的特殊项目」，然后把每一类固化进规则表，
> 换个项目照样生效。
>
> 判断标准：**规则写在这里 = 换项目不用改代码；规则没写 = 那个项目还会崩。**
>
> 最后更新：2026-11-19

---

## 一、通用逻辑的边界（先定义"什么算例外"）

引擎的通用假设只有三条，凡是违反其中一条的，就是例外，必须登记：

| 编号 | 通用假设 | 违反了会怎样 |
|---|---|---|
| A | **一个 Word 带编号的子项目 ↔ 一个报表项目**，两边金额相等 | 一对多、多对一、编号但不对报表，都会挂错或挂不上 |
| B | **子项目下的第一张表是主披露表**，取它的「合计/账面价值」行 | 主表没有合计行、或合计行叫别的名字，就取错 |
| C | **表的合计 = 上方明细之和、期末 = 期初+增−减** | 分段表（原值/折旧/净值/减值/价值）不服从 |

已经做掉的通用部分（不属于例外）：
- 章节/子项目识别、表格网格还原、期间定义解析、合并/母公司两章
- 纵向合计、其中分组、横向增减、比例重算、账面价值=余额−准备
- 报表附注号勾稽、未披露清单、TB 现金流量表核对、编号治理

## 二、已确认的例外类别（本次测试暴露的）

每条都记录：**怎么认出来 / 怎么取数 / 怎么处理 / 固化成什么样**。

### E1　一个编号覆盖多个报表项目（一对多）

| 项 | 内容 |
|---|---|
| 典型 | 「营业收入、营业成本」一节 ↔ 报表 营业收入 + 营业成本；「销售费用、管理费用、财务费用」一节 ↔ 三个费用项目；财务费用一节里的利息费用/利息收入 ↔ 报表的其中项 |
| 识别 | 子项目名按 `和/、/及` 拆分后，每个名字都能在报表里找到同名项目 |
| 处理 | 每个命中各建一条勾稽；表的列按表头里的「收入/成本」等关键字分配 |
| 固化 | `cross_checks.ALIAS_NAMES` + `fill_missing_checks`（按金额±0.01 补挂） |
| 状态 | ✅ 已实现（报表勾稽 95→105 条） |

### E2　多个报表项目共用一节（多对一）

| 项 | 内容 |
|---|---|
| 典型 | 递延所得税资产、递延所得税负债 → 附注「递延所得税资产和递延所得税负债」 |
| 识别 | 两个报表科目的附注号相同，且该编号只有一节 |
| 处理 | 同一节里按行名区分（资产行 / 负债行），不要都取合计 |
| 固化 | `report_numbering.REPORT_ITEM_ALIAS` + `ROW_HINTS` |
| 状态 | ⚠️ 编号已对上；**取行仍靠金额验证**，资产/负债两行并存时可能取错 |

### E3　「净额」行才是对外口径

| 项 | 内容 |
|---|---|
| 典型 | 租赁负债 → 表里的「租赁负债净额」；实收资本(或股本)净额 → 与实收资本同号 |
| 识别 | 报表项目名以「净额/净价」结尾，或表里存在「××净额」行 |
| 处理 | 取净额行；编号与母项一致，且**不作为独立报表项目**（不进逐项勾稽、不进未披露） |
| 固化 | `ROW_HINTS` + `NO_NOTE_ITEMS` |
| 状态 | ✅ 已实现 |

### E4　合计性质的「报表项目」（不该编号、不该勾稽）

| 项 | 内容 |
|---|---|
| 典型 | 营业总收入 / 营业总成本、营业利润 / 利润总额 / 净利润、综合收益总额 |
| 识别 | 项目名是若干明细项目之和；或利润表里上下两项明显是加总关系 |
| 处理 | 不要求附注号、不参与逐项勾稽、不进未披露清单 |
| 固化 | `report_numbering.NO_NOTE_ITEMS` |
| 状态 | ✅ 已实现（当前是枚举，**应改为"可加总判定"**，见待办 T2） |

### E5　其他综合收益组

| 项 | 内容 |
|---|---|
| 典型 | 利润表「其他综合收益的税后净额」及其子项 ↔ 附注「归属于母公司所有者的其他综合收益」 |
| 识别 | 项目名含「其他综合收益」且不是资产负债表本体的「其他综合收益」 |
| 处理 | 全部挂到该节，编号一致；该节不得反过来顶替资产负债表「其他综合收益」 |
| 固化 | `ALIAS_NAMES` + `build_cross_checks` 里的 `is_oci_group` 保护 |
| 状态 | ⚠️ 部分实现（子项还没全部挂上） |

### E6　分段式资产表（原值/折旧/净值/减值/账面价值）

| 项 | 内容 |
|---|---|
| 典型 | 固定资产、无形资产、使用权资产、投资性房地产 |
| 识别 | 表里同时出现「账面原值合计 / 累计折旧合计 / 账面净值合计 / 减值准备合计 / 账面价值合计」 |
| 处理 | ① 报表勾稽取**账面价值合计**行；② 纵向规则：净值=原值−折旧、价值=净值−减值；③ 只在「期初/期末」列核，增减列跳过 |
| 固化 | `cross_checks._total_row_of`（优先账面价值）+ `rules._rule_asset_blocks` |
| 状态 | ✅ 已实现（R-ABLK） |

### E7　现金流量表只勾一项

| 项 | 内容 |
|---|---|
| 典型 | 只有「经营活动产生的现金流量净额」与附注（现金流量表补充资料）勾，其余子项走 TB |
| 识别 | 报表为现金流量表 |
| 处理 | 其余子项标「与TB核对」，不进未勾稽、不进补配 |
| 固化 | `writer` 汇总表标记 + `fill_missing_checks` 跳过 + `tb_checks` 全量核对 |
| 状态 | ✅ 已实现 |

### E8　期间定义只写年份

| 项 | 内容 |
|---|---|
| 典型 | 「"上期发生额"指2024年度」——只有年份，没有月日 |
| 识别 | 定义句匹配 `[“"]?上期发生额[”"]?指2024年度` |
| 处理 | 补成 2024-12-31；并补齐 `PERIOD_KEYS`（上期发生额/上期金额） |
| 固化 | `table_semantics.RE_PERIOD_DEF_YEAR` |
| 状态 | ✅ 已实现 |

### E9　「其中」块要不要当报表项目

| 项 | 内容 |
|---|---|
| 典型 | 资产负债表「其中：应收股利 / 库存商品 / 固定资产原价」是明细，不算报表项目；利润表「其中：营业收入 / 其中：营业成本」是正式报表项目 |
| 识别 | 按所在报表类型区分 |
| 处理 | 资产负债表跳过「其中」块；利润表/现金流量表保留 |
| 固化 | `report_reader._sub_item_rows` 按表名生效 |
| 状态 | ✅ 已实现 |

### E10　客户数据本身不平（不是引擎的错）

| 项 | 内容 |
|---|---|
| 典型 | 长期应付款：期初+增加−减少 ≠ 期末，差额 29,036,763.69；合计行同差 |
| 识别 | 行不平且合计行同差 → 说明漏了一项（如转入一年内到期） |
| 处理 | **照实报红**，不改数、不吞掉 |
| 状态 | ✅ 这是正确行为，保持 |

## 三、待办：把例外从"代码分支"搬进"规则表"

现在 E2/E3/E5 还散落在代码里，换项目可能失效。计划新建 `special_rules.py`，用**声明式表**描述：

```python
Rule(
    code='E3',
    match={'report_item': '*净额'},              # 报表项目名模式
    row_pick=['净额', '合计', '账面价值'],        # 依次尝试的行名关键字
    number='same_as_parent',                     # 编号策略
    ratio_to_report=True,                        # 是否勾稽
    in_disclosure=False,                         # 是否进未披露清单
)
```

引擎按顺序匹配，命中即按规则执行；没命中走通用逻辑。

## 四、验收口径（比"测试项目零差异"更有意义）

| 指标 | 含义 | 当前 |
|---|---|---|
| 规则覆盖的子项目比例 | 有勾稽项的子项目 / 全部子项目 | 张江 53 个子项目，报表勾稽覆盖 40+ |
| 未挂上的报表项目数 | 汇总表里「未勾稽」行数 | 62（多数是 E1/E5 未完成） |
| 假阳性率 | 报差异中，经复核为规则错的比例 | 上一轮 16→2，其中 14 条是规则错 |
| 换项目是否要改代码 | 新增一个项目时改代码的行数 | 目标 0 |

**测试项目的意义**：每发现一类例外 → 登记一条规则 → 补一个用例。
**不是**把它的差异清到 0。
