# 财务报表审计附注核对工具 (Financial Notes Audit Tool)

面向注册会计师与审计项目组的**附注勾稽自动化**工具：把 Word 审计报告附注、
Excel 三张报表、TB 试算平衡表串起来，自动生成可追溯的勾稽底稿。

* 项目主页：https://github.com/zhanghongruiszh/financial-notes-audit-tool
* 问题反馈与交流：henryzhang825@gmail.com

---

## 设计原则

1. **不写死任何案例**。不预设章节号、不预设科目、不预设行号——全部从文档自身结构识别。
2. **模板只作参考**。5 份模板用于验证识别规则，不是运行时的必需输入；没有模板也能跑。
3. **可核对优先**。每个勾稽点紧贴在其目标科目下方，公式直接指向参与运算的单元格，
   点开公式就能定位问题；不强求与原稿列位一一对应。
4. **识别不了就说出来**。结构存疑的表在成果表里标黄并写明原因，绝不静默跳过。

## 使用方式

### 方式一：图形界面（推荐）

界面共五个按钮：

| 按钮 | 作用 |
|---|---|
| 开始自动化全面勾稽 | 选好三个文件后一键出成果 |
| Word附注编号体检与修复 | 诊断并重建 Word 附注的子项目编号 |
| 报表附注号一键修复与补全 | 按附注实际编号补齐/改正报表「附注」列 |
| 模板库 | 查看 / 导入 / 删除模板，或从 Word 重建骨架 |
| 打开输出文件夹 | 打开最近一次的项目文件夹 |

```bash
python audit_check_app.py
```

1. 选三个文件：报告附注（.doc/.docx）、财务报表（.xlsx）、TB 试算表（.xls/.xlsx）
2. 点「开始自动化全面勾稽」
3. 成果生成在 `<归档目录>/<项目名>check_v<版本号>/`

**输出文件夹内容（每版 4~6 个文件）**

```
<项目名>check_v1/
    ├── 3、审计报告附注-xxx.doc                       ← 原始导入，备查
    ├── 2、审计报告报表-xxx.xlsx                      ← 原始导入，备查
    ├── TB-试算平衡表-xxx.xls                         ← 原始导入，备查
    ├── <项目名>check_v1.xlsx                         ← 勾稽成果
    ├── 3、审计报告附注-xxx_编号已规范.docx            ← 做过「Word附注编号修复」才有
    └── 2、审计报告报表-xxx_附注编号已修复.xlsx        ← 做过「报表附注号修复」才有
```

编号治理的两个产物也落在同一个项目文件夹里，所以文件数是 **4~6 个**，取决于这次有没有做过编号治理。

两种先后顺序都成立：

* **先勾稽、后编号治理**：编号治理的产物直接写进那次的项目文件夹；
* **先编号治理、后勾稽**：产物先放在源文件旁边，勾稽时一并归档进项目文件夹。

### 编号治理与勾稽的关系（重要）

勾稽会**优先采用治理后的文件**：

* 存在 `<附注名>_编号已规范.docx` → 用它解析，按**重排后的编号**做勾稽；
* 存在 `<报表名>_附注编号已修复.xlsx` → 用它做跨表与附注号勾稽。

采用了哪一份会写进日志和成果表的「汇总表」里（"本次采用的底稿"一行），
不会悄悄换文件。

典型工作流：

1. 勾稽 → `附注号勾稽` 报出若干"不一致"
2. 跑「报表附注号一键修复与补全」→ 生成修复后的报表
3. 再勾稽一次 → `附注号勾稽` 全部一致（新的 `check_v2` 里会记录采用了两份治理后的文件）

二次核对再次运行会自动生成 `v2`、`v3`，历史版本完整保留。

## 勾稽成果表结构（4 个工作表）

刻意收拢，避免 sheet 泛滥影响可读性。

### 1. `勾稽底稿`（主体）

**与 Word 附注的顺序和版式一致**，逐表铺开。三类勾稽都体现在这张表上：

| 位置 | 内容 |
|---|---|
| 表格内**插行** | 勾稽点紧贴目标行下方插入一行 `【勾稽校验】`，写活公式（如 `=B23-(B19+B20+B21+B22)`） |
| 表格**最右侧** | 报表勾稽列：`报表数 2026-09-30 / 差额`、`报表数 2025-12-31 / 差额`…<br>报表数是**引用公式**（`='原始数据'!C293`），差额是活公式 `=(B23-C23)-K23` |
| 再往右 | TB 核对列（仅现金流量表补充资料那张表）：`TB数 / TB差额` |

配色：绿色=已平，深红=有差异，淡红底=该条有差异，黄色=结构存疑/无法确认。

### 2. `原始数据`

报表三张 + TB 现金流表的数值原样贴入，作为底稿右侧公式的引用源。
平时不用看，但点开任一"报表数"单元格就能顺着公式找回来。

### 3. `汇总表`

- 一、勾稽总览（各核对类型条数与结果）
- 二、**差异明细（带跳转链接）**——每条差异的"定位"列可点击，直接跳到 `勾稽底稿` 对应行
- 三、规则与表类型分布

### 4. `完整性`

- 一、报表项目未在附注中披露
- 二、报表「附注」列 ↔ 附注实际编号
- 三、附注内跨表 / 上下文相关项目（现金余额 vs 货币资金合计等）

## 已实现的勾稽规则

| 规则 | 含义 | 级别 |
|---|---|---|
| `V-SUM` | 合计行 = 其上方若干明细行之和（多合计行分别算；`其中：` 子块不重复计入；`减：` 取负号） | 硬 |
| `V-GRP` | 带 `其中：` 的父行 = 其下各明细之和 | 硬 |
| `H-SUM` | 合计列 = 其余列之和；若表里有「小计」列，则合计列 = 各小计列之和（不重复加明细） | 硬 |
| `R-NET` | 账面价值 = 账面余额 − 坏账准备/减值准备 | 硬 |
| `R-NBV` | 账面价值 = 账面原值 − 累计折旧/摊销 − 减值准备 | 硬 |
| `R-MOVE` | 期末 = 期初 + 本期增加 − 本期减少（行式：固定资产；列式：无形资产） | 硬 |
| `R-BLK` | **四块式变动表**（固定资产/无形资产）：①原值 ②折旧 ③减值 各自「期末=期初+增加−减少」；④账面价值 = 原值 − 折旧 − 减值 | 硬 |
| `R-PROV` | **坏账/减值准备变动表**：期末 = 期初 + 计提 − 收回或转回 − 转销或核销 | 硬 |
| `R-ECL` | **三阶段预期信用损失变动表**：期末 = 期初 + 期初余额在本期 + 计提 − 转回 − 转销 − 核销 | 硬 |
| `R-PCT` | 计提比例 = 坏账准备 ÷ 账面余额；占比 = 该行金额 ÷ 合计；**前五名表的占比分母取该项目总额（跨表引用主表合计数）** | 软（四舍五入尾差） |
| `X-NOTE` | 附注合计数 = 报表对应科目数（按科目名找行、按表头日期找列） | 硬 |
| `X-TB` | 附注现金流量表补充资料 = TB 现金流量表审定数（A.A 列） | 硬 |
| `X-NOTE-REF` | 附注内部跨表：现金期末余额 = 货币资金合计；同口径两表合计一致 | 硬 / 参考 |

容差：**金额 0.01 元；比例 0.01 个百分点**。比例不额外放宽——四舍五入到两位小数产生的
尾差能过，再大就作为差异暴露出来，由人工决定是否调整那一分钱尾差。

前五名/关联方明细表的「占比」分母是**该项目总额**，程序会去同子项目的主表合计行取数，
写成跨表活公式（例如 `=C128-(B128)/(B22)`，其中 B22 是账龄表的应收账款合计）。
只有主表排在前面的情况才能写活公式；主表在后面时会标成"待确认"而不是硬算。

**附注号只在「经营活动产生的现金流量净额」这一处挂到现金流量表**（对应
`六、22 现金流量表补充资料`）。现金流量表其余项目——现金及现金等价物净增加额、
期末/期初余额等——都是内部小项或小计，不挂附注号；它们的计算过程在 TB 里，
由 TB 现金流核对覆盖。

跨表取数口径：报表列的是**账面价值（净额）**，所以附注侧优先取「价值」列，
没有就用「账面余额 − 坏账准备」，再没有才用余额/金额——口径会写在成果表里。

TB 取数口径：TB 的 CF 表每个年度占 5 列 `（B.A） + − （A.A） 空`，
对外披露用的是 **（A.A）审定数** 那一列。

## 特殊表的加减关系（从模板结构读出来的）

固定资产、应收账款这几类表的加减方向和普通表不同，规则是**按模板里的分块结构**写的，
不依赖具体科目名：

**固定资产 / 无形资产（四块式）**

```
① 账面原值   期初 + 本期增加 − 本期减少 = 期末
② 累计折旧   期初 + 本期增加 − 本期减少 = 期末
③ 减值准备   期初 + 本期增加 − 本期减少 = 期末
④ 账面价值   期末 = 原值期末 − 折旧期末 − 减值期末
             期初 = 原值期初 − 折旧期初 − 减值期初
```

定位方式：块标题（`① 账面原值` / `② 累计折旧` / …）+ 块内「本期增加/本期减少」行；
④ 块的期初期末常写成具体日期（`2026年9月30日账面价值`），按日期与原值块对齐。

**坏账 / 减值准备变动表（列向）**

```
期末余额 = 期初余额 + 计提 − 收回或转回 − 转销或核销
```

列名不是"本期增加/减少"，所以单独一条规则；「其他变动」列有数时按加项处理。

**三阶段预期信用损失变动表（行向）**

```
期初余额
期初余额在本期      ← 转入/转回各阶段
  本期计提
  本期转回
  本期转销
  本期核销
其他变动
期末余额 = 期初 + 期初在本期 + 计提 − 转回 − 转销 − 核销
```

这是模板里出现最多的一种坏账表（83 张、3 份模板），竖着排，和上面那条列向的不是同一种排版。

### 空表 / 空列也要核算

判断一列是"金额列"还是"文字列"，**不只看有没有数**，还看表头语义：
表头含「金额 / 余额 / 期初 / 期末 / 增加 / 减少 / 计提 / 收回 / 转销 / 准备 / 价值」
等口径词的，即使整列是空的、或全是「-」，也按数值列参与核算。

这样两种常见情况不会被漏掉：

* 模板本身是空白表——结构照样解析并生成校验（只是结果为空值，不产生假差异）
* 某个项目"本期减少"整列都是「-」——`期末 = 期初 + 增加 − 减少` 照样核

实测：一般企业模板（163 张空白表）能生成 452 条校验（`R-MOVE` 103、`V-SUM` 137、
`R-NET` 76、`R-PCT` 40、`R-BLK` 23 …）。

### 尾随负号（`9,900.00-`）

Word 里常见这种写法——模板原本 0 显示成「-」，手改成数字时把「-」留在了后面。
处理方式：

* **数值照算**：`9,900.00-` 解析为 `-9900.00`，正常参与勾稽
* **单独提示**：成果表 `完整性` 的「四、数值格式异常」列出位置与原值，建议删掉「-」

不会因为它格式不规范就把整条勾稽跳过。

### 骨架提纯结果

把 5 份模板全部 2028 张表按「行标签序列 + 列结构」聚类，得到 **541 个结构家族**：

| 情况 | 表数 |
|---|---|
| 空壳（模板没填数、只有合计行） | 1105 |
| 规则已覆盖 | 714 |
| 有明细行但规则未覆盖 | 203（81 个低频家族，多为杂项表） |

各规则的覆盖表数：`V-SUM` 346、`V-GRP` 252、`H-SUM` 153、`R-NET` 134、`R-PCT` 117、
`R-ECL` 83、`R-MOVE` 78、`R-PROV` 33、`R-BLK` 14。

完整家族清单见 [docs/表结构家族.md](docs/表结构家族.md)，
重新生成：`python tools/profile_tables.py --coverage`。

实测：铁联化轻两张固定资产表各生成 30 条（3 块 × 6 列 + 2 个价值行 × 6 列），全部通过。

## 常见问题

**提示「Word 转换附注超过 120 秒没有响应」/「Excel 转换 TB 失败」**

说明调 Office 自动化时卡住了。按顺序试：

1. **关掉所有 Word / Excel 窗口**（包括后台残留的），再点一次
2. 打开任务管理器，结束残留的 `WINWORD.EXE` / `EXCEL.EXE`
3. **最稳的办法**：把附注用 Word 另存为 `.docx`、TB 用 Excel 另存为 `.xlsx`，再放进去

> 为什么第 3 条最稳：`.docx` / `.xlsx` 是**直接读取**的，完全不经过 Office。
> 实测在同一台机器上，用 `.docx` + `.xlsx` 输入时整单只需 **2 秒**；
> 只有 `.doc` / `.xls` 才需要先调 Word / Excel 转换。

程序对 Office 转换设了 120 秒超时，超时会报错并停下，不会一直卡着。

**为什么第一次运行比较慢**

`.doc` 要先用 Word 转成 `.docx`、`.xls` 要先用 Excel 转成 `.xlsx`，
第一次大约多花 20~30 秒；转换后的文件缓存在输出目录的 `_tmp` 里。

**在远程桌面 / 服务 / 受限环境里跑**

这类环境常常不允许程序驱动 Office（权限、桌面会话、Temp 目录都可能受限），
表现为 Word 卡住或 Excel 报「不能访问 INetCache」。直接用第 3 条——
准备 `.docx` + `.xlsx` 即可绕开 Office，功能完全一样。

## 关于期间（1-9 月 / 1-8 月这类非整年期间）

**不影响数字勾稽**：所有算术核对都在"同一张表、同一期间列"内部做，期间是 1-9 月
还是 1-8 月，只要同一份附注里写法一致，就一致地对齐。

三处需要注意：

1. **期间解析取区间末日**：`2026年1-9月` → `2026-09-30`，`1-8月` → `2026-08-31`。
2. **三边写法不一致时不会误判**：例如附注写 1-8 月、TB 写 1-9 月，期间对不上时
   这些条目会进「待确认」，**不会算成差异**。
3. **同一份附注里同时出现"1-9月"和"9月30日"** 会解析成同一天。跨表取数按
   「同期间 + 同角色」分组时只取第一列，这种情况目前靠"收入/成本"这类表头提示规避，
   没有通用防护——遇到时会在「待确认」里体现。

年化类指标（周转率、每股收益年化）本工具不做，所以不受非整年期间影响。

## 附注表类型识别

每张附注表会被打上类型标签，写在 `勾稽底稿` 的表标题行末尾，并在 `汇总表`
里给出全篇的类型分布。识别只看**通用披露常识**（行标签用词、列角色、表头文字、
子项目名），不依赖具体客户或模板。

| 类型 | 典型特征 |
|---|---|
| 现金流量表补充资料 | 含「将净利润调节为经营活动现金流量」 |
| 三阶段坏账变动表 | 表头有「第一阶段 / 第二阶段 / 第三阶段 / 预期信用损失」 |
| 账龄分析表 | 表头含「账龄」，行标签有「1年以内 / 1至2年 / 3年以上」 |
| 资产增减变动表 | 行有「期初 / 本期增加 / 本期减少」，或「账面原值 / 累计折旧 / 累计摊销」 |
| 坏账/减值计提表 | 列同时有「准备」与「比例」（或「价值」） |
| 前五名/关联方明细表 | 表头「债务人名称 / 单位名称」，或行标签多为公司名 |
| 所得税调整表 | 含「适用税率」或「利润总额 + 调整」 |
| 费用明细表 | 子项目是管理费用 / 销售费用 / 财务费用 / 研发费用 / 税金及附加 |
| 余额明细表 | 普通「项目 × 期间」表，有合计行 |
| 未分类 | 以上都不像（会显示在总览里，便于发现问题表） |

实测铁联化轻案例：57 张表**全部识别**，分布为余额明细表 30、账龄 10、坏账计提 6、
费用明细 3、三阶段 2、资产变动 2、现金流量表补充资料 2、前五名 1、所得税调整 1。

## 模板库（加速识别）

模板**只作加速，不是运行必需**：没有模板照样能跑（完全自主识别），
有相近模板时能把「列角色」判得更全，减少人工确认。

- **只存骨架**：`模板库/*.skeleton.json`，内容是子项目名单 + 每张表的行列数与列角色，
  不含原文（原始 .doc 共 18MB，不进包）。默认带 5 份骨架，合计约 600KB。
- **位置**：程序同目录的 `模板库/`。打包版首次运行会自动把它放在 exe 旁边。
- **可替换**：界面上点「模板库」→ 可以直接导入新的 `.doc/.docx`（自动提取骨架）、
  删除、或把新的 Word 模板丢进该目录后点「从 Word 重建骨架」。
- **怎么起作用的**：先用子项目名重合度挑最接近的模板，再用它同位置那张表的列角色，
  **只补自主识别判不出来的列**，不覆盖已有判断。

## 附注编号治理（两件事）

### 1. Word 附注编号：体检与重建

Word 附注的编号情况比想象中复杂，一共有五种，还可能互相叠加：

| 情形 | 例子 | 说明 |
|---|---|---|
| ① 正文手打编号 | `1、货币资金` | 编号就是正文文字 |
| ② Word 自动编号 | `货币资金` + 段落挂 numId | 编号来自 `numbering.xml`，正文里没有数字 |
| ③ 两者并存 | `1、货币资金` 且又挂了自动编号 | Word 里会显示成「1、1、货币资金」 |
| ④ 完全没有编号 | `货币资金`（既无文字也无 numId） | 漏号 |
| ⑤ **分段** | 同一章里 1–13 实际是「1–6」一段 +「1–7」另一段 | 编号中途重启 |

[docx_numbering.py](docx_numbering.py) 会解析 `numbering.xml` 还原**真实显示的编号**，
所以②「正文没有数字、全靠自动编号」也能正确识别；⑤「分段」会被判为
**分段重启 / 分段内编号**，而不是笼统的「重号」。

界面上「Word附注编号体检与修复」会：

1. 逐个子项目给出「自动编号 / 手工编号 / 实际显示 / 问题 / 建议编号」，
   问题类型包括：双编号、无编号、分段重启、分段内编号、重号、跳号、倒序
2. 按需把该章子项目统一重建为**从 1 连续的自动编号**：
   删掉手打编号、整章共用一个专用列表（所以⑤的分段会被合并成 1..N 连续）
3. **绝不覆盖原件**，输出 `原文件名_编号已规范.docx`，生成后立刻重新解析复核 1..N 是否连续

### 2. 报表主表「附注」列：一键修复与补全

[report_numbering.py](report_numbering.py) 从附注里识别出的子项目编号出发，
把报表主表的「附注」列**补齐或改正**：

* 章号用附注里的真实编号（可能是「六、」，也可能是「七、」「八、」「十八、」），不写死
* 合并 / 母公司报表分别用各自那一章的编号
* 只做**全等匹配**（允许去掉括号补充说明，如「实收资本（或：股本）」）；
  不做包含匹配——否则「长期应付职工薪酬」会被错配成「应付职工薪酬」的附注号，
  填错一个附注号比留空危害大得多
* 自动跳过没有任何金额的空白模板表
* 输出 `原文件名_附注编号已修复.xlsx`，不覆盖原件
